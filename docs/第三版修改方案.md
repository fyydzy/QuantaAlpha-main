# 第三版修改方案：燃气预测「对话式智能体」（编排 + 流式展示）

## 说明

把「燃气预测」从**表单驱动**升级为**对话驱动的 AI 网页**：用户只输入一句自然语言（例如「预测 2026 年 3 月河北的天然气销量」），系统自动按固定流程跑完 **意图解析 → 诊断 → 特征推荐 → 多模型比选 → 旬度预测与月度汇总 → 结果问答**，并以**对话流 + 结构化卡片**的形式逐步展示，关键节点支持人工确认/修改（human-in-the-loop）。

> 本质是**编排器（orchestrator）**，不是因子挖掘那种自主进化智能体（`LoopBase`/`Trace`）。流程固定、可控、好调试，LLM 只在「意图解析、特征推荐、结果问答」三个节点参与决策。

---

## 一、与第一/二版的关系

| 子系统 | 入口 | 第三版处理 |
| --- | --- | --- |
| 燃气业务预测 | `quantaalpha forecast` | **不改算法**，作为编排器的「执行」步被调用 |
| 特征组合实验 | `quantaalpha forecast_search` | **不改**，复用其 LLM 提案/反馈模块 |
| 按模型配特征 | 第二版 `model_features` / `resolve_model_feature_set` | **直接复用**，解决「不同模型特征不一样」 |
| 结果问答 | `POST /api/v1/forecast/qa` + `forecast_qa.py` | **复用并接入对话流** |

第三版 = **在以上模块之上新增一个「编排层 + 对话式前端」**，不动底层预测逻辑。

---

## 二、核心理念：编排器 vs 自主智能体

| | 编排式工作流（本方案） | 自主智能体（因子挖掘 `AlphaAgentLoop`） |
| --- | --- | --- |
| 步骤 | 固定 5 阶段 | LLM 自行决定下一步 |
| LLM 角色 | 意图解析 / 特征推荐 / 问答 | 规划 / 调度 / 反思 / 自循环 |
| 轮次 | 单轮（不自动迭代优化） | 多轮进化 |
| 控制性 | 高、可预测 | 低、较贵 |
| 落地代码 | 一个 orchestrator 模块 | `LoopBase` + `Trace` + 进化控制器 |

## 三、整体流程（对话式 5 阶段）

```text
用户输入: "预测2026年3月河北的天然气销量"
        │
        ▼
【阶段0 解析意图】LLM 自然语言 → 结构化参数
   province / target_month / test_start,test_end / as_of_month
        │
        ▼  ◀━━ 交互点①：助手卡片展示解析参数，用户确认或修改
【阶段1 诊断】全特征 xgboost baseline → feature_importance（gain 排序）
        │
        ▼
【阶段2 特征推荐】LLM 结合 query + 重要性 Top-K + 特征池
   → 输出「统一候选特征超集 S」+ 推荐理由
        │
        ▼  ◀━━ 交互点②：助手卡片展示推荐特征（可勾选增删），用户确认
【阶段3 投影 + 多模型比选】
   resolve_model_feature_set(model, S) 为每个模型投影特征
   runner auto 跑候选模型 → 旬度预测 → 选最优
        │
        ▼
【阶段4 旬度预测 + 月度汇总】
   旬度曲线（预测 vs 真实）+ 按月 sum 汇总 + 榜单（含各模型实际特征）
        │
        ▼  ◀━━ 交互点③：自动选最优 or 用户指定模型
【阶段5 结果问答】复用 forecast_qa，进入自由多轮对话
        │
        ▼
       完成（全程以对话流 + 卡片展示）
```

「自动」：用户发一句话，阶段 0→5 自动推进。
「交互」：①②③ 三个节点可暂停等确认；也可配置「全自动模式」用默认值跳过。

```python
@dataclass

    candidate_models: str = "xgboost,lasso,ridge,lstm,sarimax"

def parse_intent(query: str) -> dict:          # 阶段0  (LLM)
    """query -> {province, target_month, test_start, test_end, as_of_month}"""

def diagnose_importance(params: dict) -> dict: # 阶段1  (复用 xgboost_agent)
    """全特征 baseline xgboost -> feature_importance(gain 排序)"""

def recommend_features(query, importance) -> dict:  # 阶段2 (LLM, 复用 forecast_planning)
    """-> {feature_superset: [...], reason: str}"""

def run_compare(params, feature_superset) -> dict:  # 阶段3-4 (复用 runner auto)
    """resolve_model_feature_set 投影 -> auto 比选 -> 旬度 + 月度汇总 -> 榜单"""

def monthly_rollup(decade_rows) -> list[dict]: # 阶段4 (新增聚合工具)
    """旬度预测按月 sum -> 月度销量 + 月度 MAPE"""
```

每个阶段产出一条**结构化消息**推送给前端（见第六节）。

### 5.2 新增 / 复用 API

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `POST` | `/api/v1/forecast/agent/start` | 入参 `{query, province?, interactive?}`，创建对话式任务，返回 `taskId` |
| `WS` | 复用现有 forecast WebSocket | 流式推送各阶段消息（复用 `_broadcast`） |
| `POST` | `/api/v1/forecast/agent/continue` | 入参 `{taskId, stage, payload}`，交互点确认/修改后继续（如修改特征列表、指定模型） |
| `POST` | `/api/v1/forecast/qa`（已有） | 阶段 5 问答，改造为支持**多轮** |

> 实现上沿用 `app.py` 现有模式：`tasks` 字典管理状态 + `asyncio.create_task` 跑编排 + `_broadcast` 推消息。交互点通过「编排协程在确认前 `await` 一个 `asyncio.Event`，由 `/continue` 触发」实现暂停/续跑。

### 5.3 意图解析（阶段0）

- 用 LLM 把 `"2026年3月"` → `target_month=2026-03`，映射旬度 `test_start=2026-03-01 / test_end=2026-03-21`。
- `province` 缺省回退「河北」并在交互点①要求确认。
- `as_of_month`（训练截止）按规则取测试区间前最近旬开始日。
- **关键参数不静默决定**：解析结果必须经交互点①确认（除非 `interactive=false`）。

### 5.4 特征推荐（阶段1-2）

- 阶段1：先用「全特征」跑一次 `xgboost` baseline，读取其 `*_best_summary.json` 里的 `feature_importance`（已现成输出）。
- 阶段2：把 `query + 重要性 Top-K + 特征池(feature_registry.FEATURE_REGISTRY)` 喂给 LLM（复用 `forecast_planning.propose_solutions` 的 prompt 模式，改为产出**一个**超集），输出统一候选特征超集 S + 理由。
- 防幻觉：S 必须过 `feature_registry` 白名单 + `preflight_tabular_feature_set` 预检。
- 锚特征：天气外生（`HDD`/`avg_temp` 等）+ 关键滞后 `Lag_36` 设为「建议必选」，避免漏掉燃气核心驱动。

### 5.5 「不同模型特征不一样」的处理（直接复用第二版）

LLM 只产出**一个**统一超集 S，逐模型投影由现成函数完成：

```text
LLM 推荐超集 S
   ├─ tabular(lasso/xgb/lgb/cat/rf/ridge/enet) → 用完整 S
   ├─ sarimax → S ∩ SARIMAX_EXOG_COLS
   └─ lstm    → S ∩ SELECTED_FEATURES
```

实现：`resolve_model_feature_set(model, S)`（见 `[model_feature_capabilities.py](../quantaalpha/forecast_agent/model_feature_capabilities.py)`）。
比选公平性：榜单每行展示该模型**实际** `feature_cols_used`，避免「SARIMAX 只用 3 列凭什么比 MAPE」的误读 —— 比的是**各模型在自身能力域内的最优表现**。

### 5.6 月度汇总（阶段4，新增）

- 旬度预测 → 按自然月 **求和**（`gas_sales` 是销量类指标）。
- 同时给月度 `MAPE`（有真实值时）。
- 决策层通常更关心月度，旬度作为过程精度。

### 5.7 前端对话式页面

- 复用 `frontend-v2/src/components/ChatInput.tsx`（因子挖掘已有的对话输入）。
- 新增消息流容器 `ForecastChat`（或复用挖掘看板的消息渲染），按 `messageType` 渲染不同卡片（见第六节）。
- 复用现有 recharts 图组件、指标卡、`renderMarkdownLike`。

## 六、对话消息协议（结构化卡片）

WebSocket 每阶段推送一条消息，前端按 `messageType` 渲染对应卡片：

```jsonc
{
  "role": "assistant",
  "stage": "parse_intent",          // parse_intent|diagnose|recommend|compare|rollup|qa
  "messageType": "params_card",     // 决定前端渲染哪种卡片
  "text": "我理解你要预测 2026 年 3 月河北的旬度销量，请确认参数：",
  "payload": { /* 见下表 */ },
  "needConfirm": true,              // 是否暂停等待 /continue
  "timestamp": "..."
}
```

| stage | messageType | payload 关键字段 | 是否交互点 |
| --- | --- | --- | --- |
| parse_intent | `params_card` | province, targetMonth, testStart, testEnd, asOfMonth | ✅① |
| diagnose | `importance_card` | topFeatures:[{name, gain}] | — |
| recommend | `features_card` | featureSuperset:[...], reason | ✅② |
| compare | `leaderboard_card` | rows:[{model, MAPE, RMSE, featureColsUsed}] | ✅③ |
| rollup | `chart_card` | decadeCurve:[...], monthlyRollup:[...] | — |
| qa | `text`(markdown) | answer, modelUsed, rowsUsed, dataMode | 多轮 |

## 七、Human-in-the-loop 交互点

| 交互点 | 触发 | 用户可做 | 续跑方式 |
| --- | --- | --- | --- |
| ① 参数确认 | 阶段0 后 | 改省份/时间区间 | `/continue {stage:"parse_intent", payload:修正参数}` |
| ② 特征确认 | 阶段2 后 | 勾选增删特征超集 | `/continue {stage:"recommend", payload:{featureSuperset}}` |
| ③ 选模型 | 阶段4 后 | 接受最优 or 指定模型 | `/continue {stage:"compare", payload:{model}}` |

`interactive=false` 时三处全部用默认值（解析参数 / LLM 推荐 / 自动最优）自动跳过。

## 十一、风险与兜底

- **LLM 不可用**：意图解析降级为表单（高级设置），特征推荐降级为「全特征」默认，问答返回本地统计摘要。
- **意图解析出错**：交互点①强制确认，避免跑错整轮。
- **诊断 baseline 耗时**：缓存全特征 xgboost 结果，避免与比选阶段的 xgboost 重复训练。
- **token 爆炸**：问答沿用 `FORECAST_QA_MAX_ROWS` 截断；推荐 prompt 只送重要性 Top-K。
- **并发任务**：沿用 `tasks` 字典 + taskId 隔离。

---

## 十二、验收标准

- 输入一句「预测 2026 年 3 月河北销量」，无需填表即可自动跑完并在对话流中依次出现：参数卡 → 重要性 → 推荐特征 → 榜单 → 旬度图 + 月度汇总 → 可继续问答。
- 交互点②修改特征后，比选结果随之改变。
- 榜单每行显示该模型**实际使用特征**，SARIMAX/LSTM 与 tabular 模型特征不同但能正常比选。
- `interactive=false` 时全程自动、无须人工确认。
- LLM 缺 key 时，预测主流程仍可完成，仅问答/推荐降级并给出明确提示。
