# 第三版修改方案：燃气预测「对话式智能体」（编排 + 流式展示）

## 说明

把「燃气预测」从**表单驱动**升级为**对话驱动的 AI 网页**：用户只输入一句自然语言（例如「预测 2026 年 3 月河北的天然气销量」），系统自动按固定流程跑完 **意图解析 → 诊断 → 特征推荐 → 多模型比选 → 旬度预测与月度汇总 → 结果问答**，并以**对话流 + 结构化卡片**的形式逐步展示，关键节点支持**自然语言确认/修改**（human-in-the-loop）。

> 本质是**编排器（orchestrator）**，不是因子挖掘那种自主进化智能体（`LoopBase`/`Trace`）。流程固定、可控、好调试，LLM 在「意图解析、特征推荐、确认覆写解析、结果问答」四个节点参与决策。

## 二、整体流程

```text
用户输入: "预测2026年3月河北的天然气销量"
        │
        ▼
【阶段0 解析意图】LLM → 结构化参数（失败时可正则补 target_month）
        │
        ▼  ◀━━ 交互点①：对话确认/修改参数（confirm_intent）
【阶段1 诊断】全特征 xgboost baseline → feature_importance
        │              （使用覆写后的 province / test 区间）
        ▼
【阶段2 特征推荐】LLM(query + 已确认 intent + 重要性 Top-K + 特征池) → 超集 S + reason
        │
        ▼  ◀━━ 交互点②：对话确认/修改特征（confirm_features）
【阶段3 投影 + 多模型比选】
   _project_feature_superset_for_model() 逐模型投影
   runner auto → 旬度预测 → 按 MAPE 选最优
        │
        ▼
【阶段4 月度汇总】旬度 test 表按月 sum + 月度 MAPE
        │
        ▼
【阶段5 问答】ask_flow_qa() → forecast_qa.generate_forecast_qa_answer()（可选）
```

默认候选模型（`DEFAULT_AGENT_CANDIDATE_MODELS`）：

`catboost,elasticnet,lasso,lightgbm,lstm,random_forest,ridge,sarimax,xgboost`

## 三、日期与意图解析规则（已实现）

实现文件：`quantaalpha/forecast_agent/gas_forecast_flow.py` → `parse_intent()` / `apply_intent_overrides()`

### 3.1 字段含义

| 字段 | 含义 |
| --- | --- |
| `target_month` | 用户要预测的月份 `YYYY-MM` |
| `test_start` / `test_end` | 测试旬区间（旬开始日 1/11/21） |
| `as_of_month` | 训练截止旬（该日及以前的数据用于训练） |
| `province` | 省份简称，默认 `河北` |

### 3.2 解析优先级

**target_month**

1. LLM 解析结果
2. 正则从 query 提取（`2026年3月` / `2026-03`）
3. **都没有 → 直接 `ValueError`**

**test_start / test_end**

1. LLM 同时给出且通过旬日校验（1/11/21）→ 使用
2. 都未给出 → 由 `target_month` 推导：`YYYY-MM-01` ~ `YYYY-MM-21`
3. 只给一侧 → **直接报错**

**as_of_month**

- 固定为 `2025-06-21`（`FIXED_AS_OF_DATE`），不再由 query/LLM 自动推导
- CLI 不允许覆盖该值

**province**

- LLM 给出则用，并标准化简称（`河北省` → `河北`）；否则 CLI 默认 `河北`

### 3.3 覆写后参数一致性

用户在 `confirm_intent` 阶段修改参数后，由 `apply_intent_overrides()` 合并：

- 若只改 `target_month` 且未同时指定 `test_start`/`test_end` → **自动重推**旬区间
- 若同时指定 `test_start` + `test_end` → 校验旬开始日后使用
- 只指定一侧 → **报错**

覆写后的 `intent` 会传入：`diagnose_importance()` → `recommend_feature_superset(intent=...)` → `run_compare_and_rollup()`。

### 3.4 预测时间轴说明

| 区间 | 含义 | 是否计入 test MAPE |
| --- | --- | --- |
| 训练集 | `≤ as_of_month`（固定 2025-06-21） | 否 |
| bridge（桥接） | as_of 之后 ~ 目标月之前各旬 | 否（无真实值，仅滚动预测） |
| test（目标月） | `test_start` ~ `test_end` 对应三旬 | **是** |

`forecast_head` / `*_forecast.csv` 含 bridge + test 全序列；`test_metrics.MAPE` 仅在目标月 **3 个旬点**上计算，且数值已 ×100（`0.42` = **0.42%**）。

### 3.5 示例

query：`预测2026年3月河北天然气销量`

```json
{
  "province": "河北",
  "target_month": "2026-03",
  "test_start": "2026-03-01",
  "test_end": "2026-03-21",
  "as_of_month": "2025-06-21"
}
```

## 四、特征推荐与多模型投影（已实现）

### 4.1 阶段1：诊断

- 跑全特征 `xgboost` baseline（输出目录 `_diagnose_xgboost/`）
- 读取 `xgboost_best_summary.json` 中的 `feature_importance`（gain 排序）
- **不使用**用户最终确认的特征集；目的是为 LLM 推荐提供重要性证据

### 4.2 阶段2：推荐

- LLM 输入：`query` + **已确认 intent** + 重要性 Top-K + `FEATURE_REGISTRY` 特征池
- 输出：单个 `feature_superset` + `reason`
- **禁止**以测试集 MAPE 作为主推荐依据
- 默认锚特征：`HDD`、`Lag_36`（可通过 `required_features` 配置）
- **LLM 失败或返回空/非法特征 → 直接报错**

### 4.3 阶段3：逐模型投影

```text
LLM 推荐超集 S（或用户覆写后的 S'）
   ├─ tabular(xgb/lasso/lgb/cat/rf/ridge/enet) → 完整 S'
   ├─ sarimax → S' ∩ SARIMAX_EXOG_COLS
   └─ lstm    → S' ∩ SELECTED_FEATURES
```

实现：`_project_feature_superset_for_model()` → `ForecastRunConfig.model_features` → `runner.run_forecast(model=auto)`。

榜单每行展示该模型**实际** `feature_cols_used`。

### 4.4 阶段4：月度汇总

- 读最优模型 `{model}_test.xlsx/csv`
- 按自然月对 `predicted_gas_sales` / `actual_gas_sales` **求和**
- 有真实值时计算月度 `mape_pct`

## 五、人机确认与覆写解析（M3，已实现）

### 5.1 两个确认点

| checkpoint | 时机 | 用户可改 | 后端处理 |
| --- | --- | --- | --- |
| `confirm_intent` | 意图解析后、诊断前 | province / target_month / test 区间 | `apply_intent_overrides()` |
| `confirm_features` | 特征推荐后、比选前 | `featureSuperset` 完整列表 | 写回 `recommend["feature_superset"]` |

用户说「继续/好的/确认」→ `approved=true`，`overrides` 为空，按系统推荐继续。

用户说「取消/停止」→ `approved=false`，任务终止。

**已取消** `confirm_model`：比选完成后直接展示 `leaderboard_card`，不再等待用户指定模型。

### 5.2 覆写解析策略（LLM 优先）

实现文件：`gas_forecast_flow.py`

| 函数 | 职责 |
| --- | --- |
| `parse_continue_message()` | 入口：LLM 优先，失败则规则兜底补全 |
| `_continue_intent_prompt()` | 与 `parse_intent` 同风格的参数确认 prompt |
| `_continue_features_prompt()` | 与 `recommend_feature_superset` 同风格的特征确认 prompt |
| `normalize_continue_overrides()` | 字段名归一化 + 特征池白名单过滤 |
| `apply_intent_overrides()` | 合并 intent 并保持 month ↔ test 区间一致 |

### 5.3 Web 暂停/续跑

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `POST` | `/api/v1/forecast/agent/{task_id}/continue` | `{message, approved?, overrides?}` 自然语言续跑 |
| `GET` | `/api/v1/forecast/agent/{task_id}` | 轮询；`metrics.awaiting_confirmation` 表示等待中 |

- 流程内 `_wait_for_continue()` 通过模块级 `_forecast_continue_events` 暂停（**不**写入 task 字典，避免 JSON 序列化失败）
- 前端 `ForecastPage` 对话区输入回复 → `continueForecastAgentTask()`

### 5.4 阶段消息

覆写生效后额外推送：

- `intent_applied`：展示更新后的 intent
- `features_applied`：展示更新后的 featureSuperset

## 十、错误处理原则

| 场景 | 行为 |
| --- | --- |
| query 无明确月份 | **报错**，提示补全「YYYY年M月」 |
| LLM 意图解析失败但 query 有月份 | 正则补 `target_month`，继续 |
| LLM 特征推荐失败 | **报错**，不自动用重要性 Top 替代 |
| LLM 覆写解析失败 | 规则兜底补全缺失字段 |
| 只覆写 test_start 或 test_end 一侧 | **报错** |
| LSTM/SARIMAX 特征不兼容 | 比选前投影 |
| 月度汇总缺 test 表 | **报错** |
| LLM key 缺失 | 意图/推荐/覆写 LLM 阶段失败；进程内需加载 `.env` |
| GET task 返回 500 | 已修复：asyncio.Event 不得放入 task 字典 |
