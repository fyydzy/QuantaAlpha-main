# 第三版修改方案：燃气预测「对话式智能体」（编排 + 流式展示）

## 说明

把「燃气预测」从**表单驱动**升级为**对话驱动的 AI 网页**：用户只输入一句自然语言（例如「预测 2026 年 3 月河北的天然气销量」），系统自动按固定流程跑完 **意图解析 → 诊断 → 特征推荐 → 多模型比选 → 旬度预测与月度汇总 → 结果问答**，并以**对话流 + 结构化卡片**的形式逐步展示，关键节点支持人工确认/修改（human-in-the-loop）。

> 本质是**编排器（orchestrator）**，不是因子挖掘那种自主进化智能体（`LoopBase`/`Trace`）。流程固定、可控、好调试，LLM 在「意图解析、特征推荐、结果问答」三个节点参与决策。

## 二、整体流程

```text
用户输入: "预测2026年3月河北的天然气销量"
        │
        ▼
【阶段0 解析意图】LLM → 结构化参数（失败时可正则补 target_month）
        │
        ▼  ◀━━ 交互点①（M3）：展示参数卡，用户确认/修改
【阶段1 诊断】全特征 xgboost baseline → feature_importance
        │
        ▼
【阶段2 特征推荐】LLM(query + 重要性 Top-K + 特征池) → 超集 S + reason
        │
        ▼  ◀━━ 交互点②（M3）：展示推荐特征，用户可增删
【阶段3 投影 + 多模型比选】
   _project_feature_superset_for_model() 逐模型投影
   runner auto → 旬度预测 → 按 MAPE 选最优
        │
        ▼
【阶段4 月度汇总】旬度 test 表按月 sum + 月度 MAPE
        │
        ▼  ◀━━ 交互点③（M3）：接受最优 or 指定模型
【阶段5 问答】ask_flow_qa() → forecast_qa.generate_forecast_qa_answer()
```

默认候选模型（`DEFAULT_AGENT_CANDIDATE_MODELS`）：

`catboost,elasticnet,lasso,lightgbm,lstm,random_forest,ridge,sarimax,xgboost`

## 三、日期与意图解析规则（已实现，无重兜底）

实现文件：`quantaalpha/forecast_agent/gas_forecast_flow.py` → `parse_intent()`

### 3.1 字段含义

| 字段 | 含义 |
| --- | --- |
| `target_month` | 用户要预测的月份 `YYYY-MM` |
| `test_start` / `test_end` | 测试旬区间（旬开始日 1/11/21） |
| `as_of_month` | 训练截止旬（该日及以前的数据用于训练） |
| `province` | 省份，默认 CLI 参数 `河北` |

### 3.2 解析优先级

**target_month**

1. LLM 解析结果
2. 正则从 query 提取（`2026年3月` / `2026-03`）
3. **都没有 → 直接 `ValueError`**（不再回落到 `TEST_END` 默认月）

**test_start / test_end**

1. LLM 同时给出且通过旬日校验（1/11/21）→ 使用
2. 都未给出 → 由 `target_month` 推导：`YYYY-MM-01` ~ `YYYY-MM-21`
3. 只给一侧 → **直接报错**

**as_of_month**

- 固定为 `2025-06-21`（`FIXED_AS_OF_DATE`），不再由 query/LLM 自动推导
- CLI 不允许覆盖该值（覆盖会直接报错）

**province**

- LLM 给出则用；否则 CLI 默认 `河北`

### 3.3 示例

query：`预测2026年3月河北天然气销量`

```json
{
  "province": "河北",
  "target_month": "2026-03",
  "test_start": "2026-03-01",
  "test_end": "2026-03-21",
  "as_of_month": "2025-06-21"
}
```

### 3.4 LLM Prompt 约束

- 未知字段填 `null`，不要臆造
- `test_start` / `test_end` / `as_of_month` 若填写，必须是旬开始日（1/11/21）
- 数据层 `data.cli_date_to_period()` 会二次校验

## 四、特征推荐与多模型投影（已实现）

### 4.1 阶段1：诊断

- 跑全特征 `xgboost` baseline（输出目录 `_diagnose_xgboost/`）
- 读取 `xgboost_best_summary.json` 中的 `feature_importance`（gain 排序）

### 4.2 阶段2：推荐

- LLM 输入：`query` + 重要性 Top-K + `FEATURE_REGISTRY` 特征池
- 输出：单个 `feature_superset` + `reason`
- **禁止**以测试集 MAPE 作为主推荐依据
- 默认锚特征：`HDD`、`Lag_36`（可通过 `required_features` 配置）
- **LLM 失败或返回空/非法特征 → 直接报错**（不用重要性 Top 静默兜底）

### 4.3 阶段3：逐模型投影（解决「不同模型特征不一样」）

LLM 只产一个超集 S；比选前在编排器内投影：

```text
LLM 推荐超集 S
   ├─ tabular(xgb/lasso/lgb/cat/rf/ridge/enet) → 完整 S
   ├─ sarimax → S ∩ SARIMAX_EXOG_COLS
   └─ lstm    → S ∩ SELECTED_FEATURES
```

实现：`_project_feature_superset_for_model()` / `_project_feature_superset_by_model()`  
写入 `ForecastRunConfig.model_features` 后调用 `runner.run_forecast(model=auto)`。

榜单每行应展示该模型**实际** `feature_cols_used`。

### 4.4 阶段4：月度汇总

- 读最优模型 `{model}_test.xlsx/csv`
- 按自然月对 `predicted_gas_sales` / `actual_gas_sales` **求和**
- 有真实值时计算月度 `mape_pct`
- 缺表或缺列 → **直接报错**（不返回空列表）

## 九、错误处理原则（与代码一致）

| 场景 | 行为 |
| --- | --- |
| query 无明确月份 | **报错**，提示补全「YYYY年M月」 |
| LLM 意图解析失败但 query 有月份 | 正则补 `target_month`，继续 |
| LLM 特征推荐失败 | **报错**，不自动用重要性 Top 替代 |
| LSTM/SARIMAX 特征不兼容 | 比选前投影，不应再报「未知列」 |
| 月度汇总缺 test 表 | **报错** |
| LLM key 缺失 | 意图/推荐阶段失败；需配置 `.env` 或显式传参 |
