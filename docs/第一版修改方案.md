## 说明

增加一个“LLM 生成特征组合 → 固定模型批量跑 → 排行榜 → LLM 总结”的最小闭环（用于做特征组合选择实验）。

> 关键原则：**不要把燃气预测硬塞进 `AlphaAgentLoop` 的因子循环**；燃气预测保持独立，通过新增一个 `forecast_search`（或 `forecast_search`）子命令来做方案搜索实验即可。

# 一、第一版实现的功能范围

## 第一版实现 6 个功能


| 功能              | 说明                                                      |
| --------------- | ------------------------------------------------------- |
| **特征池（可选特征列表）** | 基于现有 `build_features_pipeline()` 产出的列名 + 允许 LLM 选择的白名单  |
| **LLM 生成候选方案**  | 输入研究目标（如“春节后复工影响”），输出 N 个 feature_set 方案                |
| **方案合法性校验**     | 禁止使用不存在特征；禁止 `date/month/gas_sales` 等不可用列               |
| **固定模型批量运行**    | 每个方案都跑同一个后端（建议 `xgboost` 或 `random_forest`），便于比较特征带来的变化 |
| **方案指标排序**      | 按 `test_metrics.MAPE`（或 `score`）排序出 top-k               |
| **结果反馈与保存**     | 保存方案库、排行榜、以及 LLM 的“为什么该方案更好”的解释                         |


## 第一版暂时不做


| 暂时不做                     | 原因                                               |
| ------------------------ | ------------------------------------------------ |
| **多模型同时比较**              | 目标是验证“特征组合选择”，不是先做模型大赛（仓库现有 `auto` 已支持多模型）       |
| **自动生成新特征公式**            | 先保证可控、可复现、可解释；新特征先人工实现进 `feature_engineering.py` |
| **mutation / crossover** | 先跑通最小闭环再上进化策略                                    |
| **前端页面大改**               | 第一版先走 CLI + JSON 输出；Web UI 可后续增强显示排行榜            |
| **月度预测**                 | 当前只保留旬度（`date`=旬开始日）                             |

# 二、第一版整体流程

```text
quantaalpha forecast_search
        ↓
读取 configs/forecast_search.yaml
        ↓
构建“可选特征池”（基于 feature_engineering + 白名单）
        ↓
forecast_planning.py 调用 LLM
生成 N 个特征组合方案（solution_001...）
        ↓
校验 feature_set 合法（必须在可选特征池内）
        ↓
solution_search.py 循环执行每个方案
        ↓
固定 model = xgboost（或 random_forest）
并将 feature_set 注入到该后端的训练输入列选择中
        ↓
读取每个方案的 test_metrics（MAPE/RMSE/MAE/R2）
        ↓
按指标排序
        ↓
forecast_feedback.py 调用 LLM 生成结果分析
        ↓
输出 solution_library.json / solution_leaderboard.csv / feedback.md
```

说明：

- **现有 `quantaalpha forecast` / `runner.run_forecast()` 不需要改动行为**：仍用于正常业务预测（含 `auto` 多模型）。
- `forecast_search` 是“实验工具”，输出目录建议独立到 `forecast_agent_output/{province}/solutions/`，避免污染正常预测输出。

# 三、LLM 在第一版中负责

LLM 只负责两件事：

## 1) 生成特征组合方案（feature_set）

示例研究目标：


## 3. `forecast_planning.py`

### 功能

调用 LLM，从已注册特征池中生成候选组合。

### 输入

```python
goal = config.goal  # 来自 forecast_search.yaml，由用户/业务填写，可随任务变化
```

**Prompt 里必须把「可选特征列表」完整交给 LLM**（建议 JSON：`name` + `description`），让模型根据 `goal` 自行组合，而不是在 prompt 里写死「必须含春节复工」等句式。

### 输出

```python
list[ForecastSolution]
```

### LLM Prompt 模板（推荐）

下面用占位符；实现时用代码把 `{{FEATURE_POOL_JSON}}`、`{{GOAL}}` 等替换掉。

```text
你是旬度天然气销量预测的特征方案设计助手。

【研究目标】（由配置文件提供，每次可不同）
{{GOAL}}

【可选特征池】（只能从中选择，不得使用列表外的名称）
{{FEATURE_POOL_JSON}}

请提出 {{N}} 个彼此有差异的候选特征方案。每个方案需给出：
- solution_id（如 solution_001）
- name（简短中文名）
- hypothesis（为什么这组特征可能改善上述目标）
- feature_set（从特征池中选取的列名数组）

硬性约束：
1. feature_set 中的每个名称必须出现在【可选特征池】中；
2. 每个方案特征数量不超过 {{MAX_FEATURE_COUNT}}；
3. 不得发明新特征名、不得写 Python/公式、不得修改特征定义；
4. 输出为严格 JSON 数组，不要 markdown 包裹。

可选约束（若配置非空则追加到 prompt 或在校验阶段强制执行）：
- 每个方案必须包含：{{REQUIRED_FEATURES}}（为空则忽略）
```

**示例 `goal`（仅作演示，不是系统默认值）：**

```text
改善春节后及三月上旬的旬度预测误差，重点考虑低温、采暖季和节后复工。
```

此时 LLM 可能**自行**选用 `spring_rework_peak`、`HDD_cross_spring_rework_peak` 等；若换目标为「夏季非供暖季误差」，则应改 `goal`，而不是改 prompt 里的春节条款。

### 程序校验函数

```python
def validate_solution(
    solution: ForecastSolution,
    *,
    allowed: set[str],
    required_features: list[str],
    max_feature_count: int,
) -> None:
    selected = set(solution.feature_set)

    unknown = selected - allowed
    if unknown:
        raise ValueError(f"LLM 使用了未注册特征: {unknown}")

    missing = set(required_features) - selected
    if missing:
        raise ValueError(f"方案缺少配置要求的特征: {missing}")

    if len(selected) > max_feature_count:
        raise ValueError("单个方案特征数量超过限制")

    if len(selected) == 0:
        raise ValueError("feature_set 不能为空")
```

**不建议**在代码里写：`必须包含 spring_rework_peak`、`必须有一个 baseline 方案` 等——这类逻辑应完全由 `goal` + LLM 推理 + 可选 `required_features` 表达。

## 4. `solution_search.py`

### 功能

这是第一版最核心的新模块，负责完整执行流程。

```python
def run_feature_solution_search(config):
    goal = config.goal
    fixed_model = config.model

    # 1. LLM 生成方案
    solutions = propose_solutions(
        goal=goal,
        fixed_model=fixed_model,
    )

    # 2. 校验方案
    for solution in solutions:
        validate_solution(solution)

    # 3. 固定同一个模型逐个运行
    results = []
    for solution in solutions:
        run_config = ForecastRunConfig(
            province=config.province,
            as_of_month=config.as_of_month,
            test_start=config.test_start,
            test_end=config.test_end,
            model=fixed_model,
            solution_id=solution.solution_id,
            solution_name=solution.name,
            hypothesis=solution.hypothesis,
            feature_set=solution.feature_set,
        )

        result = run_forecast(run_config)
        results.append({
            "solution": solution,
            "result": result
        })

    # 4. 排序
    ranked_results = rank_solutions(results)

    # 5. 生成反馈
    feedback = generate_feedback(
        goal=goal,
        ranked_results=ranked_results,
    )

    # 6. 保存结果
    save_solution_library(
        goal=goal,
        fixed_model=fixed_model,
        ranked_results=ranked_results,
        feedback=feedback,
    )

    return ranked_results
```

## 5. `solution_evaluator.py`

### 第一版排名依据


```python
def rank_solutions(results: list[dict]) -> list[dict]:
    ranked = sorted(
        results,
        key=lambda item: item["result"]["test_metrics"]["MAPE"]
    )

    for rank, item in enumerate(ranked, start=1):
        item["rank"] = rank

    return ranked
```

# 十二、如何运行

## 1）准备环境

在项目根目录：

```powershell
cd E:\4.1\internship2\智能体框架\QuantaAlpha-main
$env:SETUPTOOLS_SCM_PRETEND_VERSION_FOR_QUANTAALPHA = "0.1.0"

# 安装主项目 + 预测依赖（含 xgboost / torch 等）
uv sync --extra forecast
```

确保你的 LLM API Key 已写入项目根目录 `.env`（推荐），仓库的 `APIBackend()` 会自动读取。

把项目根目录 `.env` 按下面这样填（最小可用版本，只需要 1 行）：

```dotenv
OPENAI_API_KEY=sk-xxx
```

可选项（需要时再加）：

```dotenv
# 代理/兼容接口服务时填写
# OPENAI_BASE_URL=https://api.openai.com/v1

# 指定使用哪个模型（不填则默认 gpt-4-turbo）
# CHAT_MODEL=gpt-4o-mini

# 可选：预测数据目录（省份 Excel 所在目录）
# FORECAST_DATA_DIR=.\data\processed_data
```

## 2）编辑配置

修改 `configs/forecast_search.yaml`，至少确认：

- `goal`
- `forecast.province / as_of_month / test_start / test_end`
- `forecast.model`（第一版建议固定 `xgboost` 或 `random_forest`）
- `analysis.enabled: true`（自动生成总结）

## 3）一条命令运行（生成 leaderboard + feedback）

```powershell
uv run quantaalpha forecast_search --config configs/forecast_search.yaml
```

默认输出会写到 `forecast_agent_output/{province}/` 下（见 `configs/forecast_search.yaml` 的 `output.*` 配置）：

- `solution_leaderboard.csv`
- `solution_library.json`
- `forecast_feedback.json`
- `forecast_feedback.md`
