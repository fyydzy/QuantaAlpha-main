# 第四版修改方案：燃气预测从编排器升级为 Agent

## 1. 目标与范围

第四版目标：在不回退现有第三版能力（两次确认、比选、问答、Web 对话展示）的前提下，把当前"固定阶段编排"升级为"状态驱动、工具化、可扩展"的 Agent 运行时。

---

## 2. 已完成改造（MVP Agent Runtime）

### M1：状态模型与检查点（FlowState）✅

- 新增 `FlowStage` 枚举，覆盖全部阶段（parse_intent → confirm_intent → intent_applied → data_loading → diagnose → recommend → confirm_features → features_applied → compare → qa → completed/failed）
- 新增 `FlowState` 数据结构，每个阶段结束写 `flow_checkpoint.json`
- 任务元数据中透出 `lastCheckpoint`、`checkpointPathDisplay`、`auditPathDisplay`
- 保持现有消息协议兼容（不破坏前端展示）

### M2：工具化阶段函数（Tool Wrapper + Registry）✅

- 统一工具层 `call_forecast_tool(tool_name, ...)` 封装
- 工具列表：`parse_intent`、`diagnose_importance`、`recommend_feature_superset`、`run_compare_and_rollup`、`ask_flow_qa`
- 编排逻辑固定顺序，但调用口统一；新工具可通过注册表接入，不改主流程骨架

### M3：审计与可观测性（flow_audit.jsonl）✅

- 每步记录：阶段、工具名、开始/结束时间、耗时、输入摘要、输出摘要、错误信息
- 在 task metrics 透出审计文件路径（`auditPathDisplay`）
- 任意失败任务可定位在哪一步、为什么失败

### M4：LLM 调用统一封装与轻量重试 ✅

- 统一 JSON 解析、异常格式化、重试策略（默认轻量重试）
- 适配节点：意图解析、continue 解析、特征推荐、结果问答

### M5：后端 API ✅（已精简，不含 resume）

已实现接口：
- `POST /api/v1/forecast/agent/start` — 启动预测智能体
- `GET /api/v1/forecast/agent/{task_id}` — 查询任务状态与检查点
- `DELETE /api/v1/forecast/agent/{task_id}` — 取消任务
- `POST /api/v1/forecast/agent/{task_id}/continue` — 在人机确认点继续

> `POST /api/v1/forecast/agent/{task_id}/resume`（从检查点恢复）已从第四版中移除。

### M6：前端最小增强 ✅

- 两次人机确认点（参数确认、特征确认）交互完整
- 阶段卡片附加工具执行摘要（耗时/状态）
- 实时进度、WebSocket 推送、5s 轮询兜底
- 任务状态徽章、日志面板、问答追问

## 3. 流程架构

```
用户输入
   ↓
parse_intent（LLM 解析意图）
   ↓
[确认点①] confirm_intent（用户确认/修改省份、目标月）
   ↓ [如有修改] intent_applied
   ↓
data_loading（加载历史数据）
   ↓
diagnose（xgboost 全特征重要性诊断）
   ↓
recommend（LLM 推荐特征组合）
   ↓
[确认点②] confirm_features（用户确认/修改特征）
   ↓ [如有修改] features_applied
   ↓
compare（多模型并行比选 + 月度汇总）
   ↓
[可选] qa（问答追问）
   ↓
completed / failed / cancelled
```

## 5. 已移除的能力

- **从检查点恢复（resume）**：前后端均已删除。取消任务后需重新开始预测。
- 量化因子挖掘、回测、因子库等模块（第三版遗留，已清理）

---

## 6. Advanced（后续演进方向，暂未实现）

1. **Planner Loop**：由受约束 LLM Planner 决定下一步 `tool_call` / `finish`
2. **预算策略**：`max_llm_calls`、`max_tokens`、`max_runtime`、`max_model_trials`
3. **恢复策略**：工具级重试 + 计划级回退（例如推荐失败回落到重要性 Top-K 保底）
4. **记忆分层**：
   - 短期：会话上下文 + 最近工具输出
   - 长期：历史 case（省份、月份、特征组合、最优模型、误差）
5. **前端 Agent 事件流**：从 stage card 逐步升级到 `plan_step/tool_call/tool_result/reflection/human_gate`

---

## 7. 风险与控制

1. 风险：改造面大影响现网
   - 控制：保留第三版接口与消息协议，采用兼容 facade
2. 风险：LLM Planner 不稳定
   - 控制：先 MVP 固定编排，后开启受约束 Planner
3. 风险：状态分散导致维护复杂
   - 控制：FlowState 作为单一事实源，所有关键步骤落 audit 与 checkpoint
