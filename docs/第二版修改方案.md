# 第二版修改方案：燃气预测按模型配置特征

## 说明

在 **常规燃气预测**（`quantaalpha forecast`）中，为每个后端模型支持可配置的输入特征列；`model: auto` 时各候选模型可各自使用不同特征子集。

> **不改** `forecast_search`（LLM 特征组合实验）。该流程仍固定 `model: xgboost` 等既有逻辑，仅复用底层 `resolve_feature_columns`。

---

## 一、第二版功能范围


| 功能                    | 说明                                                                                                      |
| --------------------- | ------------------------------------------------------------------------------------------------------- |
| **YAML 按模型配特征**       | `configs/forecast.yaml` 新增 `model_features`：`model名 -> 列名列表` 或 `null`                                   |
| **runner 注入 task**    | `ForecastRunConfig.feature_set_for_model()` → `ForecastTask.feature_set`                                |
| **tabular 全后端**       | lasso / elasticnet / ridge / xgboost / lightgbm / catboost / random_forest 统一 `resolve_feature_columns` |
| **SARIMAX / LSTM 规则** | 外生列取交集；LSTM 仅允许 `SELECTED_FEATURES` 子集                                                                  |
| **结果可追溯**             | `*_best_summary.json` 含 `feature_set`、`feature_cols_used`                                               |
| **向后兼容**              | 未配置 `model_features` 时行为与改版前一致                                                                          |


---

## 二、整体流程

```text
configs/forecast.yaml
  model: auto
  model_features:
    xgboost: [HDD, Lag_36, ...]
    lasso: [HDD, month_sin, ...]
        ↓
runner.run_forecast()
        ↓
对每个 candidate：
  feature_set = config.feature_set_for_model(model)
  预检 tabular 列名（可选 feature_set 非空时）
  ForecastTask(feature_set=...)
        ↓
*_agent._prepare_train_and_future(..., feature_set=...)
  → resolve_feature_columns → train_df[feature_cols]
        ↓
{output_dir}/{model}/*_best_summary.json
```

---

## 三、配置示例

```yaml
model: auto
candidate_models: xgboost,lasso,ridge,lstm,sarimax

model_features:
  xgboost:
    - HDD
    - Lag_36
    - is_heating_season
    - avg_temp
  lasso:
    - HDD
    - Lag_36
    - month_sin
    - month_cos
  lightgbm: null   # 全部 tabular 数值特征
  lstm:
    - Lag_36
    - HDD
  sarimax:
    - HDD
    - avg_temp
```

**解析规则**：

- 非空列表 → 写入 `ForecastTask.feature_set`
- 缺失 / `null` / `[]` → 空列表，agent 使用默认行为
- tabular 模型在运行前校验列名是否存在于特征工程后的表

## 四、模型能力分级


| 级别  | 模型                                                                   | `model_features` 行为                                |
| --- | -------------------------------------------------------------------- | -------------------------------------------------- |
| A   | lasso, elasticnet, ridge, xgboost, lightgbm, catboost, random_forest | 非空 → 子集；空 → `tabular_feature_columns` 全列           |
| B   | sarimax                                                              | 非空 → 与 `SARIMAX_EXOG_COLS` 交集；空 → 全部外生列            |
| C   | lstm                                                                 | 非空 → 须为 `Lag_36,HDD,is_heating_season` 子集；空 → 默认三列 |
| D   | timesfm                                                              | 忽略配置（单变量）                                          |


实现见 `[quantaalpha/forecast_agent/model_feature_capabilities.py](../quantaalpha/forecast_agent/model_feature_capabilities.py)`。

uv sync --extra forecast

## 八、补充方案：燃气预测页新增 LLM 问答（基于预测/真实表格）

> 目标：在“燃气预测”页面新增一个问答区，用户输入 `query`，系统把当前预测结果表格（真实值 + 预测值）提供给 LLM，返回解释性回答。  
> 模型与密钥从 `.env` 读取，默认复用现有 LLM 配置键。

### 1) 功能边界

- 仅支持“当前任务结果”问答（不跨任务历史对话）。
- 输入为单轮 `query`，输出为单轮 `answer`（无记忆）。
- 数据源优先使用 `*_test.xlsx/csv`（含真实值与预测值）；若无真实值，降级到 `*_forecast.csv` 并在回答前提示“仅含预测值”。
- 不改核心预测算法，只新增后处理解释能力。

### 2) `.env` 配置建议

优先复用现有键，避免新增过多配置：

- `OPENAI_API_KEY`
- `OPENAI_BASE_URL`（可选，兼容代理/私有网关）
- `CHAT_MODEL`（用于问答，如 `gpt-4o-mini` / 内部模型名）

可选新增（建议）：

- `FORECAST_QA_ENABLED=true`（功能开关）
- `FORECAST_QA_MAX_ROWS=120`（送入 LLM 的最大行数）

### 3) 后端改造点（`frontend-v2/backend/app.py`）

新增接口（建议）：

- `POST /api/v1/forecast/qa`

请求体建议：

```json
{
  "outputDir": "forecast_agent_output/河北",
  "model": "lstm",
  "query": "为什么 2025-12 到 2026-01 偏差较大？",
  "selectedFeatures": ["Lag_36", "HDD", "is_heating_season"]
}
```

处理流程建议：

1. 复用现有 `_load_forecast_test_points_for_ui()` 读取表格。
2. 组装结构化表格（`ds/period/yhat/y/error_pct`）。
3. 截断到 `FORECAST_QA_MAX_ROWS`（默认 120），避免 token 爆炸。
4. 组装特征上下文并一并送入 LLM：
   - `feature_cols_used`（优先从 `*_best_summary.json` 读取，表示“实际训练列”）
   - `selectedFeatures`（前端本次勾选列，可选，用于解释“配置意图”）
   - 若二者不一致，prompt 中显式提示“以 `feature_cols_used` 为准”。
5. 生成 system + user prompt，调用 LLM。
5. 返回 `answer`、`model_used`、`rows_used`、`data_mode(test_only/pred_only)`。

响应体建议：

```json
{
  "success": true,
  "data": {
    "answer": "...",
    "modelUsed": "gpt-4o-mini",
    "rowsUsed": 27,
    "dataMode": "test_only",
    "featureColsUsed": ["Lag_36", "HDD", "is_heating_season"]
  }
}
```

### 4) Prompt 设计建议

System 约束（重点）：

- 角色：燃气预测结果分析助手。
- 只能基于给定表格回答；不能编造外部事实。
- 必须指出结论依据的时间段和误差指标（例如 `MAPE`、`error_pct`）。
- 若数据不足（无真实值），明确声明“结论仅基于预测值”。

User prompt 结构建议：

- 用户问题 `query`
- 表头定义（字段含义）
- JSON 行数组（截断后）
- 特征上下文：
  - `selectedFeatures`（用户选择，若有）
  - `feature_cols_used`（模型实际训练使用）
- 输出格式要求（3-6 条要点 + 1 条行动建议）

### 5) 前端改造点（`frontend-v2/src/pages/ForecastPage.tsx`）

新增模块（放在“预测 vs 真实”图下方）：

- 输入框（query）
- “提问”按钮（调用 `/api/v1/forecast/qa`）
- 回答展示区（markdown/plain text）
- 状态提示（加载中 / 错误）

前端调用参数建议：

- `outputDir`: 当前任务 `task.config.outputDir`（无则回退 `forecast_agent_output/${province}`）
- `model`: `metrics.display_model || model`
- `query`: 用户输入

### 6) 安全与稳定性

- 不回传完整原始 Excel，仅回传必要字段表格。
- 限制 query 长度（如 <= 1000 chars）。
- 限制最大行数与超时（如 30s）；
- 失败兜底：返回“LLM 暂不可用 + 可读的本地统计摘要”。

### 7) 验收标准

- 有测试集真实值时，问“误差最大在哪些旬”可给出具体旬与误差百分比。
- 无真实值时，回答明确提示“仅预测值，无法比较真实偏差”。
- `.env` 缺失 key 时，接口返回明确错误，不影响预测主流程。
- 同一任务重复提问可稳定返回（不报路径/文件缺失错误）。
